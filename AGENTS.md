## HDL controlled dynamism, AOT and memory

Preserve the experimental source-to-SystemVerilog scope, explicit unsupported-feature diagnostics and backend-local source. Use canonical `.atto` for new guest fixtures; retain legacy `.ores` only for tested migration compatibility. Follow the [HDL static allocation checklist](docs/AOT_ZERO_GC_DYNAMISM.md). Runtime eval, class/method injection, unbounded reflection, unknown proxy targets, interpreter fallback and dynamic code emission are inadmissible in synthesis-directed AOT. Finite dispatch, compile-time macros and ownership-safe state machines require actual supported hardware lowering.

Treat removal of legacy operators and migration of tooling to Rust as targets, not already completed changes; preserve existing verification tooling until replacements are tested. Do not claim full-language AOT or zero-GC from bounded hardware synthesis, or hosted actor/tenant execution from HDL. Require exact-source simulation/synthesis evidence for hardware support; zero-step jobs are **NOT_EXECUTED**.
